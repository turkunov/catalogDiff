# Абляции разметчика — результаты 2026-10-23

Дизайн: `docs/superpowers/specs/2026-10-23-labeler-ablations-design.md`. Конфиг: `experiments/ablations.yaml`.
Сырые результаты на сервере: `/data/pseudolabel/ablations/2026-10-23/` (`<variant>.jsonl` по парам, `report.md`).

## Условия

- Eval set: 160 пар, отобранных пользователем в инструменте ручной разметки (классы 1 — 21, 2 — 41, 3 — 36,
  4 — 26, 5 — 36). Метки — пример, не выверенная разметка. Порог позитива — 4.
- Базовая модель — Qwen3.5-9B; 8 H100: 9B на GPU 0, 1, 2, 6; 4B — 3; Qwen2.5-VL-7B — 4; InternVL3.5-8B — 5; 27B — 7.
- По ходу пришлось поменять общие для всех вариантов настройки (в профиле `sofas`):
  - лимит ответа 1024 → 4096 токенов: 9B с thinking не успевала ответить;
  - сэмплирование для thinking по рекомендации Qwen (temperature 0.6, top_p 0.95, top_k 20) вместо почти жадного:
    рассуждение зацикливалось;
  - budget forcing (как в s1): если рассуждение упёрлось в лимит, оно закрывается `</think>` и модель сразу
    отвечает. Без этого у 9B 16–35% пар оставались без класса; сейчас — 0.
- Метрики: точное совпадение, ±1, квадратичная каппа (QWK), precision/recall/F1 при пороге 4. Сравнение с базой —
  на тех же парах: бутстрэп-интервал разницы точного совпадения и McNemar по правильности бинарной метки.
  `s/pair` — время пары под общей нагрузкой (несколько вариантов на одном сервере), сравнимо только грубо.

## Что видно

- **Шум.** Повтор базы отличается на +0.01 [−0.05, +0.07]. Всё, что у 9B в пределах ±0.07 от базы, от шума
  не отличить — это все абляции 1–5, сегментация и скептик.
- **Модель важнее протокола.** Qwen3.5-27B: 0.74 точного совпадения (+0.17, p = 0.001), F1 0.88 против 0.73.
  4B ≈ 9B. Qwen2.5-VL-7B (0.36) и InternVL3.5-8B (0.30) заметно хуже; InternVL почти всё отправляет в класс 2
  (класс 5 — 0 из 36).
- **Только фото (1).** Точное совпадение то же, но recall позитивов падает 0.61 → 0.45 и класс 4 почти пропадает
  (0.35 → 0.08). Текст помогает отличить «очень похожи» от «похожи по параметрам» — часть меток 4–5 опирается на то,
  чего на фото не видно. Для ученика, который смотрит только на фото, это источник шума. Статистически пока не
  значимо (McNemar p = 0.22).
- **Шаги 1–2 (2, 3) на 9B не помогают.** Один шаг: 0.60 (+0.04), precision 1.00, вдвое быстрее (20 против 38 с).
  Без шага 1 — 0.56, без шага 2 — 0.59.
- **Без thinking (4):** −0.07 (p = 0.13), в 10 раз быстрее (3.7 с на пару), но больше ложных позитивов
  (precision 0.74 против 0.90).
- **Примеры (5):** три примера «Каприз» не помогают (−0.01), класс 3 хуже (0.22 против 0.33).
- **Сегментация:** SAM3 и BiRefNet обе −0.04; SAM3 снижает recall до 0.48 (иногда отрезает части дивана —
  подушки, подлокотники), BiRefNet чаще захватывает соседние предметы. Разметчику вырезанный объект не помогает.
- **Скептик (идея 11):** понизил 6 из 42 позитивов: 3 раза правильно, 3 — ошибочно. Итог — ноль, +38% токенов.

| вариант | доля < 0.7 | доля < 1.0 | точность при ≥ 0.7 | точность при < 0.7 | AUROC |

| m_qwen35_27b (thinking) | 0.00 | 0.01 | 0.74 | — | 0.57 |
| no_thinking (9B) | 0.08 | 0.51 | 0.50 | 0.38 | 0.59 |
| m_qwen25vl_7b | 0.53 | 0.99 | 0.43 | 0.30 | 0.62 |
| m_internvl35_8b | 0.13 | 0.55 | 0.31 | 0.24 | 0.66 |

После рассуждения вероятность выбранного класса практически всегда 1.0, так что для моделей с thinking подсветка
по logprobs не срабатывает и ничего не различает (AUROC ≈ 0.5). Без thinking распределение информативно: при
уверенности ниже 0.7 точность падает (0.38 против 0.50 у 9B без thinking). Подсветка в интерфейсе сделана
(вкладка Labels: порог, фильтр, отправка в очередь `low_confidence:<profile>`), но для разметчика с thinking нужен
другой сигнал уверенности — например, голосование нескольких прогонов (идея 12, не в плане).

## Оговорки

- 160 пар и метки-пример: различия меньше ±0.07 не значимы; выводы — про направление, не про величину.
- Время пары зависит от того, сколько вариантов делили сервер; для оценки стоимости смотрите токены:
  9B ≈ 2000 токенов ответа на пару на шаге сопоставления, без thinking ≈ 120.
