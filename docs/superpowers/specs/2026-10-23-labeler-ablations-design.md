# Абляции разметчика и новые опции пайплайна — дизайн

Дата: 2026-10-23. Продолжение `2026-10-23-pseudo-labeling-loop-design.md`.

## Зачем

Показать, что пайплайн позволяет ставить эксперименты над разметчиком, и получить первые цифры:
что даёт каждая часть трёхшагового разметчика, насколько важны thinking, примеры, размер и семейство
модели, вырезание объекта с фона. Попутно в пайплайн добавляются четыре вещи, которые пользователь решил
оставить: уверенность разметчика с ручной доразметкой, шорткат «одно и то же фото», сегментация объекта
(SAM3 и BiRefNet) как опция и «скептик» для позитивов.

Качество эталонной разметки сейчас не существенно, эксперименты делаются для примера (решение пользователя).

## Решения пользователя

- Базовая модель для абляций — `Qwen/Qwen3.5-9B`.
- Абляции: 1 только фото; 2 один шаг и без шага 1; 3 без шага 2; 4 без thinking; 5 примеры; 7 модели.
- Модели для абляции 7: Qwen3.5-4B, Qwen3.5-9B, Qwen3.5-27B, Qwen2.5-VL-7B, InternVL3.5-8B.
- Уверенность: если нет сильной уверенности в одном классе — явно подсвечиваем и даём разметить вручную.
- Шорткат «одно и то же фото» — делаем.
- Сегментация объекта SAM3 — опционально; BiRefNet (салиентная) — наравне с SAM3. Доступ к SAM3 через HF-токен
  пользователя (лежит в `.env` на сервере, в репозиторий не попадает).
- Из идей 6–15 берём только 11 — «скептик» для позитивов. Остальные идеи (1–10, 12–15) не делаем.
- Поиск энкодером на сегментированных фото — исключён.
- Использовать все 8 GPU сервера.
- Eval set — 160 пар, сокращённых пользователем в инструменте ручной разметки.

## Набор для оценки

`/data/eval160/pairs160.csv` (колонки инструмента разметки) и `/data/eval160/labels160.csv`
(экспорт инструмента). Классы: 1 — 21, 2 — 41, 3 — 36, 4 — 26, 5 — 36. Порог позитива для метрик — 4.
Ни один из трёх примеров профиля `sofas` в eval set не входит.

## Варианты (все на Qwen3.5-9B, если не сказано иначе)

| Вариант | Что меняется относительно базы |
|---|---|
| `base` | текущий пайплайн: шаг 1 (фото → атрибуты), шаг 2 (текст → недостающие параметры), шаг 3 (сопоставление), thinking, без примеров |
| `base_repeat` | то же, свои кэши — шум между прогонами |
| `photo_only` (1) | текст не используется нигде: нет шага 2, в шаге 3 нет заголовков, описаний и параметров |
| `one_step` (2) | только шаг 3: фото, тексты и параметры как в данных; атрибутов с фото нет |
| `no_visual_step` (2) | без шага 1; шаг 2 есть |
| `no_text_step` (3) | без шага 2: параметры как в данных, пустые остаются пустыми |
| `no_thinking` (4) | thinking выключен (включается JSON-режим) |
| `few_shot` (5) | в шаг 3 добавлены 3 примера профиля: обе картинки, заголовки и верный класс |
| `sam3` | все фото заменены вырезанным объектом (SAM3, текст `sofa`) |
| `birefnet` | все фото заменены вырезанным объектом (BiRefNet) |
| `skeptic` (идея 11) | после `base`: пары с классом ≥ 4 проходят вторую проверку «найди отличия»; итог — меньший из двух классов |
| `m_qwen35_4b`, `m_qwen35_27b`, `m_qwen25vl_7b`, `m_internvl35_8b` (7) | конфигурация `base` на другой модели; `base` = 9B |

Примеры в профиле до этого изменения в промпт не попадали (только в демо), поэтому абляция 5 — «база без примеров
против трёх примеров». [поправка к сводке в чате]

Qwen2.5-VL-7B не умеет thinking — работает без него. InternVL3.5-8B — в штатном режиме без thinking
(`OpenGVLab/InternVL3_5-8B`). [моё решение]

## Метрики

На каждый вариант: точное совпадение, ±1, квадратичная каппа, precision/recall/F1 при пороге 4, матрица ошибок,
число сбоев, среднее время пары, суммарные токены ответа, время прогона. Сравнение с `base` на тех же парах:
McNemar по правильности бинарной метки и бутстрэп-интервал для разницы точного совпадения. Для уверенности:
AUROC «уверенность → правильность» и доля подсвеченных пар при разных порогах. Срез по эталонному классу.

## Уверенность

На шаге 3 запрашиваются logprobs (top-5) ответа. В токене цифры класса после `"class":` берутся вероятности
цифр 1–5 и нормируются — получается распределение по классам; уверенность — максимум. Пара подсвечивается,
если уверенность ниже порога, который задаёт пользователь (по умолчанию 0.7 — моё решение, как с порогом
позитива: явно виден и меняется в интерфейсе). Подсвеченные пары видны во вкладке Labels с фильтром и попадают
в очередь ручной разметки; ручная метка имеет приоритет над VLM, как и сейчас.

## Шорткат «одно и то же фото»

Перцептивный хэш (DCT, 64 бита) обоих фото; расстояние Хэмминга ≤ порога (по умолчанию 6, подбирается на
eval set — моё решение) → класс 5 без вызова VLM, источник метки `photo_dup`. Доля таких пар (5% — моё решение)
всё равно проходит VLM, чтобы мерить точность шорткaта. На eval set — precision/recall против эталонных пятёрок
для порогов 0–16.

## Сегментация

Опция профиля/эксперимента: `segmentation: none | sam3 | birefnet`. SAM3 (`facebook/sam3`, transformers) с
текстовым промптом объекта категории (`object_prompt` профиля, для диванов `sofa`); берётся экземпляр с
наибольшей уверенностью. BiRefNet (`ZhengPeng7/BiRefNet`) — салиентная маска, порог 0.5. По маске: кроп по
рамке с отступом 5% и белый фон. Если маска меньше 2% кадра — остаётся исходное фото. Вырезанные фото
кэшируются на диске и используются во всех шагах, где есть фото.

## Скептик

Для пар, которым шаг 3 дал класс ≥ 4: второй вызов с обоими фото и текстами и первым ответом; роль —
придирчивый проверяющий, который ищет отличия модели или модификации. Итоговый класс — меньший из двух.

## Развёртывание

Восемь H100: 9B — четыре экземпляра vLLM (GPU 0, 1, 2, 6; на GPU 0 рядом приложение с энкодером и
сегментацией, поэтому `gpu-memory-utilization` 0.8), 4B — GPU 3, Qwen2.5-VL-7B — GPU 4, InternVL3.5-8B —
GPU 5, 27B — GPU 7 (существующий `pl-vllm`). Отдельный compose-файл `docker-compose.ablations.yml`.
Параллельность запросов на вариант — 16.

## Не делаем

Обучение; поиск энкодером на сегментированных фото; идеи 1–10 и 12–15; калибровка порога уверенности по
конформным множествам.
